# Emulator format references

Verified against public source on 2026-09-30. The application's mappings come from the user-supplied configs; these references establish the meaning of device identifiers and connection fields.

- **BizHawk:** [SDL2Gamepad](https://github.com/TASEmulators/BizHawk/blob/master/src/BizHawk.Bizware.Input/SDL2/SDL2Gamepad.cs) creates `X{SDL device index + 1}` prefixes for SDL game controllers. They are not necessarily the Windows XInput slot. The supplied config identifies itself as 2.11.1. `BizHawk.Bizware.Input.dll` metadata identifies modern SDL builds without executing their managed code; older 2.x builds before 2.10 use Windows XInput slots. The four `AllTrollers*` sections are extracted from the supplied config. The N64/Ares64 connection-field shapes and active Ares controller value come from that config as well.
- **Eden:** [SDL driver](https://github.com/eden-emulator/mirror/blob/master/src/input_common/drivers/sdl_driver.cpp) removes the name CRC at GUID bytes 2–3 and counts ports separately for each GUID. Both SDL2-era and SDL3-era APIs are supported. The detector follows the relevant Eden raw-input and Xbox HIDAPI hints. [Input profiles](https://github.com/eden-emulator/mirror/blob/master/src/yuzu/configuration/input_profiles.cpp) and [config loading](https://github.com/eden-emulator/mirror/blob/master/src/frontend_common/config.cpp) explain why nonempty per-game profile names override global assignments. `custom/*.ini` input-profile selections are cleared to inherit the managed global assignments; unrelated per-game settings remain intact.
- **Flycast:** [SDLGamepad](https://github.com/flyinghead/flycast/blob/master/core/sdl/sdl_gamepad.cpp) uses `sdl_joystick_{instance ID}` as its unique ID. [GamepadDevice](https://github.com/flyinghead/flycast/blob/master/core/input/gamepad_device.cpp) reads/writes the corresponding `maple_` setting in `[input]`. The app uses a fresh SDL2 enumeration and rejects instance-ID gaps, since IDs from a long-running process cannot be transferred safely to a new one. This is a best-effort match across two fresh processes, not a persistent hardware ID. `device1..4` are set to controller/none while subdevices and mappings remain intact. The supplied config demonstrates controller value `0` and none value `10`.
- **SDL:** [SDL_JoystickGetPlayerIndex](https://wiki.libsdl.org/SDL2/SDL_JoystickGetPlayerIndex) exposes XInput's user index for XInput-backed controllers. [RawInput](https://github.com/libsdl-org/SDL/blob/SDL2/src/joystick/windows/SDL_rawinputjoystick.c) returns `-1` from its device-player-index accessor. General SDL player indices cannot be treated as proven XInput slots. The app identifies the XInput/RawInput GUID backend, matches exact slots first, and assigns unmatched Xbox devices in SDL order. Ambiguous device counts fail preparation.
- **Playnite:** [Pre-launch scripts](https://api.playnite.link/docs/manual/features/scriptingSupport/scriptingSupportOverview.html) execute synchronously, and an exception cancels startup. The integration gets the selected emulator's `InstallDir` through the SDK and expands Playnite variables before starting the executable. It waits for exit and drains both output pipes.

The embedded baseline files intentionally contain only controller data. Full originals, emulator binaries, native dependency downloads, and build artifacts are ignored by Git.
